# TokenFuse 1.0.3

This release brings the money path and the appliance fixes merged after
1.0.2 into the published gateway and control plane. The umbrella crate and
both client SDKs move to 1.0.3 with no client behavior change. The frozen
names in `compat/1.0.json` do not change.

## Fixed

- A cancelled request no longer loses its run or unit reservation. The
  settlement guard owns both until a known outcome; if dispatch may have
  happened but no response status arrived, it retains the exposure and shows
  it in `GET /v1/runs` (`retained`, `retained_usd`) for reconciliation (#304).
- The gateway reads complete SSE events, including multiline `data:` fields,
  and nets OpenAI cached tokens correctly when their details arrive after the
  prompt count (#306).
- A unit's current-month spend is seeded from the control plane when the
  gateway starts. Telemetry waits in a bounded, in-memory queue during a
  transport outage and is replayed in order after recovery. Unit ownership
  reaches the control plane's owner view (#310).
- The control plane reports a run that stops calling after an observed cadence
  as one `run_stalled` incident. The new event type is registered across the
  agent-event consumers (#307, agent-passport#66, trailryx#77).
- The gateway reports an events-file open failure, and the released images
  use the group expected by the launchers' record directory. An overlong
  on-behalf-of chain is refused at both doors (#303).

## Upgrade notes and limits

- Both gateway and control-plane images must be upgraded together for the
  monthly seed and unit-owner view. The launchers need their own pin updates;
  tagging this repository does not change a running installation.
- The settlement guard retains an unknown outcome, but there is no admin
  reconciliation route yet. Retained reservations are process-local. A
  gateway restart still loses the run ledger; the monthly unit spend can be
  seeded from the control plane, subject to that plane being reachable at
  startup.
- A `send` error is still treated as not dispatched even when the provider
  may have received the call. Clean streams without final usage and usage
  preceding a body error remain under review (#308, #309). No claim of
  complete provider-charge accounting is made for these cases.
- The control plane has no explicit run-finished signal. A normally completed
  run without an outcome tag or final refusal can produce one medium
  `run_stalled` incident after its cadence threshold.
- The raft backend is optional and is compiled out of the shipped gateway
  image. This release does not establish parity with the in-process ledger.
