# TokenFuse 1.20.2

A patch release. A call to `gpt-6.1-terra` is now priced at its own row instead of the conservative fallback, and the build carries a newer `zstd-sys` plus a recorded, expiring exception for two zstd advisories that cannot be fixed yet. Upgrading is recommended for every deployment that routes calls to `gpt-6.1-terra`; for the others it changes nothing you can see.

It covers everything merged since v1.20.1: pull requests #484, #486, #487, #488 and #489. Pull request #485 moved the README badge, the README examples and the compose pins to v1.20.1 after that tag existed. This release moves them to v1.20.2 in a post-tag pull request, once the tag and its images exist.

`compat/1.0.json` and `components.json` are unchanged since v1.20.1.

## Upgrade

Read this section before you change the image tag.

1. No configuration changes and no migration. Change the image tag.
2. If you route calls to `gpt-6.1-terra` (or `openai/gpt-6.1-terra` through OpenRouter), expect lower numbers from the first call on the new image. Until now the model had no row, so every call was estimated, reserved against the budget and recorded at the fallback price of 15 / 75 USD per million tokens (input / output), and the response said `x-fuse-price: fallback`. It is now priced at its own rate, so a call costs about a fifteenth of what it was recorded at, budgets burn that much more slowly, and the header no longer says `fallback` for it.
3. An operator row for the model in `TOKENFUSE_PRICE_BOOK` still wins over the built-in row, and (as for every built-in row with a long-prompt tier) replaces the base rate and drops the tier. Nothing else about that file changes.

## Pricing

- `gpt-6.1-terra` is priced at OpenAI's Standard list, read from the vendor's pricing page on 2026-10-28 (USD per million tokens): up to 272K prompt tokens, input 1.00, output 5.00, cached input 0.05, cache write 1.25; above 272K, input 2.00, output 7.50, cached input 0.10, cache write 2.50. As for every OpenAI row, the one-hour cache-write column is the write rate. The `openai/gpt-6.1-terra` name carries the same price (#488).
- `GET /v1/price-book` and `contracts/tokenfuse-constants.json` list the row and its tier under both names (116 base rows and 25 long-prompt tiers, from 114 and 23).
- The vendor's page now also lists a 12-hour cache-write column. The book still treats OpenAI as having one cache write rate, for this row as for every other OpenAI row, and has not decided whether that column is a second tier it should price.

## Dependencies

- RUSTSEC-2026-0410: zstd-sys 2.0.13 to 2.1.2 (#487). The advisory concerns the wasm32 allocator shim, which this repository does not build for; the bump clears the finding.
- RUSTSEC-2026-0391 (zstd 0.13.3) and RUSTSEC-2026-0403 (zstd-safe 7.2.1) are ignored in `.cargo/audit.toml` as a temporary accepted risk (#487). The fixed versions, zstd 0.14.3 and zstd-safe 8.2.0, need parquet and arrow-ipc 60, and the newest DataFusion release (55.2.0) pins them to 59. The only crates that depend on zstd are parquet and arrow-ipc 59.3.0, whose library code uses only the bulk API of zstd, which neither advisory concerns. That is a reading of their source, not a run.
- The exception expires. `scripts/audit.sh` now fails if parquet or arrow-ipc 60 or later appears in a lockfile while the two ignores remain, if zstd leaves 0.13.x or zstd-safe leaves 7.x, if either is in no lockfile, or if any crate other than the named callers depends on them. Nine teeth cases pin those rules. The exit is DataFusion 56 or any release that takes parquet and arrow-ipc 60, and the ignores are deleted in the same change that moves to it (invariant 11).
- zstd-safe stays at 7.2.1 on purpose: 7.2.2 and later fall inside the affected range of a further advisory that 7.2.1 sits outside of.

## Other changes

- CI is shorter: teeth baselines are taken once, the suite is counted once for the stated-numbers cases, and the shards are balanced by measured seconds. Nothing was removed or weakened; the same cases run, plus those for the new code (#489).
- The pinned GitHub Actions were bumped: dtolnay/rust-toolchain, docker/login-action 4.7.0, ossf/scorecard-action 2.5.0, github/codeql-action upload-sarif 4.39.1, actions/setup-python 7.1.0 and pypa/gh-action-pypi-publish 1.14.3 (#486).
- A test pins that a keyryx checkpoint statement with no signatures is refused; no product code changed (#484).

## Not measured

- No live run of this release yet. It has not been run against a live deployment or a live OpenAI response; the `gpt-6.1-terra` price is proven by unit tests that pin the row, its long tier and the OpenRouter name, and by the regenerated published contract, not by a recorded call.
- That the two ignored zstd advisories do not reach the gateway rests on reading the 59.3.0 sources of parquet and arrow-ipc. It was not exercised with a hostile zstd stream.
- The new `zstd-sys` and the bumped Actions were exercised by this repository's CI. The release workflow (`docker/login-action`, the toolchain pin) and the publish workflows have not run with the new pins; the tag build is their first run.
