# TokenFuse 1.13.2

A patch release with one fix on the Cloud's control-plane page, one TLS dependency fix and a few stale texts corrected.

## Fixed

- **The control-plane page no longer reads run fields as markup (invariant 102).** The page the Cloud serves at `GET /` built its runs table as HTML, with each run's `run_id` and `model` written into it. Both are chosen by whoever calls a gateway, so a caller-chosen value reached the operator's browser as markup. The page now sets run fields as text. Every other value it shows was already set as text or passed through a fixed encoder, and the gateway and the Next.js dashboard serve no caller-built HTML.
- **`rustls` moves from 0.23.45 to 0.23.46 in both lockfiles (RUSTSEC-2026-0346, -0347, -0348, -0349).** The four advisories cover client session values whose Debug output exposed TLS secrets, application data sent to an outer server after an Encrypted Client Hello rejection, Brotli certificate decompression that could allocate up to 1 GiB before authentication, and an unauthenticated ServerHello that could downgrade later connections to classical key exchange. `Cargo.toml` is unchanged and no other crate version moves.
- **Stale texts on the control-plane page.** The key field no longer suggests `devkey`, a fallback removed in v1.9.0; it reads "org API key". The savings tile reads "Saved" with its breakdown "all time", because the total has no month boundary.

## Changed

- The GitHub Actions pins moved: the CI actions group (six updates), and in the release workflow `actions/upload-artifact`, `actions/download-artifact` and `anchore/sbom-action`. This is the first tag cut on the new release-workflow pins.
- The repository checks gained a gate that keeps served pages from building markup out of data (`scripts/no-html-from-data.sh`, invariant 102), and the public-text gate now reads Rust raw strings.
- Comments in the Rust sources were reworded, and the Cloud gained tests for the page. Apart from the page fix, no behavior changed.

## Upgrade

Replace the image tag. No configuration changes. `components.json`, `contracts/` and `compat/` are unchanged since v1.13.1, so no environment name, route, header or contract moves. The umbrella crate and both client SDKs move to 1.13.2 with no client behavior change.

## Not proven

- The page fix was checked in a browser against a local stub control plane. No deployed Cloud was run on this image.
- No live gateway or provider call was made on the new image for this release.
- The rustls move is held by the CI audit and build of both lockfiles; no run of a live TLS connection through a released image was made here.
