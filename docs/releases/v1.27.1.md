# TokenFuse 1.27.1

A patch release. The Cloud's published OpenAPI contract now caps the replay event's delegation chain at the length agent-passport SPEC 5.1 allows, and the repository measures its test coverage against a floor and runs a weekly mutation sweep. Nothing in the gateway's or the Cloud's behaviour changes.

The release covers everything merged since v1.27.0: pull requests #544 to #549 and the commits they carry.

## Upgrade

1. Change the image tag. No setting, environment variable or stored state changes.

## Contract

- **`ReplayEvent.on_behalf_of` carries `maxItems: 32` (#549).** agent-passport SPEC 5.1 caps the `on_behalf_of` chain at 32 entries. The replay event was published as an array with no bound, so the contract described a chain of any length; the schema now states the cap, and a test in `crates/cloud/tests/it/openapi.rs` holds it. The gateway already refused a longer chain; this is the published description catching up. The iPhone and Watch app's copy of the contract carries the same bound (tokenfuse-mobile#18). `CallRecord.on_behalf_of` keeps the raw `X-Fuse-On-Behalf-Of` header as one string and is unchanged.

## Testing

- **A coverage floor and a weekly mutation sweep (#545, #546, #547).** CI measures line coverage and fails below a ratcheting floor. A weekly `cargo-mutants` run takes its baseline once and then runs in eight shards, each test binary capped at 8 GiB of address space.
- The suite runs 2727 tests (cloud 401), one more than v1.27.0: the contract test above.
