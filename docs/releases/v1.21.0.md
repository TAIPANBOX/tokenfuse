# TokenFuse 1.21.0

A minor release with two additions and one dependency fix. The agent firewall now takes a run's taint label from the act an enforcement point saw, not from the tool name the agent reported. A provider that keeps failing is now one incident in the Cloud console and API instead of one `dependency_failed` per call. wasmtime moves to 49.0.5 for three advisories.

It covers everything merged since v1.20.3: pull requests #494 to #498. Pull request #494 moved the README badge, the README examples and the compose pins to v1.20.3 after that tag existed. This release moves them to v1.21.0 in a post-tag pull request, once the tag and its images exist.

`compat/1.0.json` and `components.json` change additively: one Cloud route, one gateway route and two `TOKENFUSE_` names are added, and nothing is renamed or removed.

## Upgrade

Read this section before you change the image tag.

1. No migration. Change the image tag.
2. Labels from a provider's answer. The gateway now reads `server_tool_use` and `mcp_tool_use` blocks in a provider's answer, buffered and streamed, and labels the run before that answer's own tool calls are judged. A run that used a provider's built-in search carried no label before and carries one now, so a shell asked for in the same answer, or later in that run, is judged with the label. This applies to every deployment, with or without a classification. The OpenAI wire carries its built-in search as `annotations` and no tool block, so it is not read.
3. Labels from the MCP broker are opt-in. Nothing is classified until you set `TOKENFUSE_MCP_UPSTREAM_LABELS`, for example `TOKENFUSE_MCP_UPSTREAM_LABELS="search=web"` for an upstream named `search` (`default` names the default upstream). It needs `TOKENFUSE_MCP_TAINT_GATEWAY`. The broker refuses to start on a value it cannot read, on a name that matches no upstream, and on a classification with no taint gateway.
4. With a classification set, a `tools/call` to a classified upstream must name its run in `x-fuse-run-id`. A call that names none is refused before anything is forwarded. An answer whose label the gateway did not take is withheld, and a gateway with the firewall off answers `governed: false` and the answer returns.
5. The tool name map still applies, and a run carries the union of both signals. The event contract does not change: the record is the existing `taint_raised` event, with stage `mcp_tool_call` for the broker and `model_tool_call` for the provider.
6. Provider failures reach the Cloud. A gateway with `TOKENFUSE_CLOUD_URL` and `TOKENFUSE_CLOUD_KEY` set counts the calls its provider fails (a 5xx, 408 or 429 answer, or a send that failed) and reports the count to `POST /v1/provider-failures` every two seconds, with the Cloud key it already holds. That key must be an `ingest` or `admin` key; a viewer key gets a 403. A report that cannot be delivered is dropped, not queued. The per-call `dependency_failed` event on the agent-event bus is unchanged.
7. In the Cloud, a provider that has failed `TOKENFUSE_CLOUD_INCIDENT_PROVIDER_FAILURES` calls (default 3; unset, zero or an unreadable value is the default) within ten minutes opens one incident, `dependency_failed:provider:<host of TOKENFUSE_UPSTREAM>`, with `@<site>` appended for a key bound to a site. It is severity `high`, carries the failures folded as `occurrences`, and shows on the console, `GET /v1/incidents`, the stream and push like any incident. It names a provider and no agent or run, so it is not on the agent-event bus. If you alert on Cloud incidents, expect this one where there was none.

## Added

- The label of a run comes from the act (#495, invariant 143, `scripts/taint-comes-from-the-act.sh`). A fetch reported under a name the policy trusts no longer carries that name's labels alone, and a fetch left out of the conversation no longer carries none. The MCP broker made the connection, so it reports which classified server answered to the new `POST /v1/fuse/observed-act`, whose closed body has no member for a tool name. The provider's own answer is the second witness. A label follows an act that passed through an enforcement point. A provider's built-in search is labelled and not controlled, because it runs on the provider's infrastructure.
- A provider that keeps failing is one incident (#498, invariant 144). The new Cloud route `POST /v1/provider-failures` is held to a hostile caller: 401 with no key, 403 for a viewer, a 16 KiB body limit answered with 413 before the body is read, at most 64 entries, a count that is not a non-negative integer refused with 400, and a provider label cut to 128 characters and reduced to `A-Za-z0-9._:-`. Providers past 64 per organisation fold into one visible `other` bucket rather than evicting a real one. The label is the host and port of `TOKENFUSE_UPSTREAM` with any `user:password@` removed, and the report carries a fixed class such as `HTTP 503` and never the text of an error, which can carry the upstream URL.

## Security

- wasmtime 49.0.5 for RUSTSEC-2026-0422, RUSTSEC-2026-0423 and RUSTSEC-2026-0424 (#496). It is the fixed patch of the line `Cargo.toml` already asked for, so only `Cargo.lock` moves. wasmtime sits behind the optional `wasm` feature, which no shipped image builds.
- A run's taint can no longer be decided only on a tool name the agent chose (#495). See Added.

## Also in this release

- The classification fixtures of the MCP broker tests name no optional add-on, so the request-path scan in estate-gates reads clean (#497). No behaviour changes.
- A comment in `proxy.rs` now says that each call is its own run, so a notifier window keyed on the run mails once per call (#498).
