# TokenFuse 1.25.0

A minor release. Under `TOKENFUSE_AGENT_TOKENS=require`, a call made on behalf of a person now has a door: the person's delegation rides beside the agent's own token, and the policy plane receives the person's chain as proven. The price book also gains a row for Claude Fable 5.2.

It covers everything merged since v1.24.0: pull request #524 (the delegation header pair, invariant 147), #522 (the Fable 5.2 price row) and #515 (a CI action bump). Pull request #521 moved the README and the cloud compose file to v1.24.0 after that tag existed. `components.json` does not change. `compat/1.0.json` gains two names in its experimental agent-token entry; nothing frozen moves.

## Upgrade

Read this section before you change the image tag.

1. No migration. Change the image tag.
2. **Nothing changes for a client that sends neither new header.** The two headers below are read only when an agent token admitted the call. A static-key call, a client-proof-of-possession call and a call with no credential behave as before.
3. **A client that acts for a person sends two more headers.** `x-fuse-delegation` holds the person's vouchryx delegation token. `x-fuse-delegation-dpop` holds that delegation's own RFC 9449 proof: made with the same key as the agent token's proof, for this request, naming the delegation in `ath`. The agent token and its proof travel as before (`Authorization: DPoP <agent token>` and `DPoP`). A client signs two proofs per request, each with its own `jti`.
4. **A proxy in front of the gateway must forward both new headers.** The gateway forwards neither of them upstream.
5. **A delegation alone is still not a door credential.** Under `require` the agent token is the credential; the delegation is read beside it.

## Security

- **A person's delegation is held to the agent token's key and agent (#524, invariant 147).** `chainproof::resolve_at_door`, which both the LLM door and the MCP broker call, proves the chain from the delegation only when it verifies (signature, issuer, audience, expiry, binding, proof), names itself in its proof's `ath`, carries the agent token's key (`cnf.jkt` equal), names the agent token's `sub` as its last actor, uses its proof once (the agent-token door's replay cache), passes the revocation list for every party it names, and agrees with a declared `x-fuse-on-behalf-of`.
- **Wardryx judges the person.** The decide request carries the delegation's `on_behalf_of` with `chain_proven: true` beside `identity_source: agent-token`, so `require_root_principal`, `max_chain_depth` and `deny_if_chain_unproven` apply to the person's chain. Events carry the delegation's `delegation_proof`.
- **The second header is refused where no agent token admitted the call.** A static key, client proof of possession and no credential get `401 delegation_refused`. It is also refused as a second credential at the XAA door and when repeated, and ignored when no issuer is configured.

## Pricing

- **Claude Fable 5.2 is priced (#522).** Calls to `claude-fable-5-2` were billed at the 15 / 75 fallback; the row is 8 / 40 USD per million tokens (cache read 0.20, cache write 10.00 for 5 minutes and 16.00 for 1 hour). The bare Bedrock id `anthropic.claude-fable-5-2` carries the page's 10 percent regional premium.
