# TokenFuse 1.5.0

Three changes from the 2026-10-04 estate audit, each closing a place where the
gateway looked configured and was not: a mistyped budget mode, a run budget the
agent chose for itself, and a policy plane that was told a tool's name and
nothing about the call. It is a minor because it adds two operator settings
(`TOKENFUSE_MAX_RUN_BUDGET_USD`, `TOKENFUSE_MCP_WARDRYX_TIMEOUT_MS`), one
response header (`x-fuse-budget-clamped`) and one optional member of the policy
decide request (`tool_call`). All are additive: nothing frozen in
`compat/1.0.json` moves, and a deployment that sets nothing new behaves as it
did on 1.4.1, with the one exception under Upgrade. The umbrella crate and both
client SDKs move to 1.5.0 with no client behavior change.

## Fixed

- **A mistyped `TOKENFUSE_MODE` stops the gateway from starting (#351,
  invariant 72).** The gateway matched only the exact words `enforce` and
  `warn` and read everything else as `shadow`, so `enfroce`, `Enforce` or
  `ENFORCE` started a gateway that blocked no budget while its operator
  believed it did. Unset or empty is still `shadow`. The three names are now
  read in any case, and anything else exits 2 naming the value, the same answer
  `TOKENFUSE_IDENTITY_STRICT` already gives. Every launcher sets `enforce`
  explicitly, so none is affected.

## Added

- **An operator ceiling on the budget a caller declares for its run (#352,
  invariant 73).** A run's budget came from `x-fuse-budget-usd`, the header the
  agent sends, and the next call of an open run could widen it, so in a
  deployment with no client keys, no identity map and no unit caps the per-run
  ceiling was whatever the agent said. `TOKENFUSE_MAX_RUN_BUDGET_USD` (a
  positive decimal with at most six decimals, read as exact microdollars) now
  clamps a budget that came from the caller header, the policy default or the
  built-in USD 5 default to that figure, on every call, so widening an open run
  reaches the ceiling and no further. A budget that comes from the Cloud is the
  operator's own word and is never clamped, and a caller may always ask for
  less. A clamped call's answer, a refusal or a stream included, carries
  `x-fuse-budget-clamped: <ceiling>` in exact dollars (for example `1.00`); the
  header is absent on a call that was not clamped. The clamp is logged once per
  run. An unreadable value (`0`, a sign, `1e9`, a second point, a seventh
  decimal, a word) exits 2 naming the variable.
- **The MCP broker tells the policy plane which call it is about to make (#353,
  invariant 74).** The policy decide request for a `tools/call` carried the tool
  name only. It now also carries an optional `tool_call` object
  `{name, arguments, target}`: `arguments` is what the agent sent, taken before
  any vault secret is injected, so a `{{secret:NAME}}` handle reaches the policy
  plane as that text and never as the value; `target` is the upstream the call
  goes to (the `X-Fuse-Mcp-Upstream` name, else the default upstream's host and
  port, never the URL). The serialized arguments are capped at 16 KiB: over the
  cap the object is sent without `arguments` and with `arguments_truncated:
  true`, never a prefix of the JSON, and the upstream still receives the whole
  call. Only the broker sends it; the model path's request has no `tool_call`.
  A decide that carries one waits up to `TOKENFUSE_MCP_WARDRYX_TIMEOUT_MS`
  (unset, blank or unusable means the shared `TOKENFUSE_WARDRYX_TIMEOUT_MS`).
  wardryx ignores unknown members of its decide request, so this and a wardryx
  that reads `tool_call` can ship in either order.

## Maintenance

- **Main is green again on a current toolchain (#350).** The README names the
  current release, the optional `wasm` dependency moves to wasmtime 49.0.2
  (five advisories against 47.0.4; the feature is in no shipped image), and
  `async-trait` moves to 0.1.92 for the clippy lint rustc 1.99 added.

## Upgrade

- **`TOKENFUSE_MODE` now refuses a typo at start.** A hand-written deployment
  that carried a wrong value, one that ran as `shadow` without anybody noticing,
  will now exit 2 at start and name the value. Correct it to `shadow`, `warn` or
  `enforce` (any case). A deployment that left it unset, or set one of the three
  names, is unchanged. Check the variable before upgrading a deployment that was
  not built from a launcher.
- **The ceiling is off unless set.** Without `TOKENFUSE_MAX_RUN_BUDGET_USD` a
  caller still chooses its own per-run budget, exactly as on 1.4.1. The
  launchers do not set it yet; until they do, a launcher deployment is no more
  bounded than before. A client that reads response headers can look for
  `x-fuse-budget-clamped` to learn that its declared budget was lowered.
- **`TOKENFUSE_MCP_WARDRYX_TIMEOUT_MS` is optional.** Nothing to change; set it
  only to give tool calls a longer policy deadline than model calls.

## Not proven

- The ceiling is one figure per run, not per agent: an agent that opens a new
  run id gets a new ceiling's worth, so it bounds each run and not an agent's
  total spend. That needs unit caps or a budget bound to an identity.
- None of the three was run against a real model provider (the stub provider
  only) or on a live cluster. The ceiling was not run end to end on the
  `cluster` feature with the variable set.
- The claim that wardryx ignores unknown decide members is from reading its
  source at `36df366`, not from sending it a `tool_call`.
- The policy decision cache key does not include the arguments: a policy whose
  answer depends on them must answer `cacheable: false`, or its verdict is
  reused for other arguments of the same tool until the TTL ends.
- "The secret value never reaches the policy plane" covers vault secrets only.
  A raw secret the agent typed into the arguments itself is sent when
  `TOKENFUSE_MCP_DLP` and `TOKENFUSE_MCP_DLP_PII` are `shadow` or `off`. Object
  key order in `arguments` may differ from the agent's bytes, and duplicate keys
  collapse.
- Nothing here makes a policy use `tool_call`, and no added latency was
  measured.
- A launcher run with a mistyped `TOKENFUSE_MODE` was not performed, because none
  ships one.
