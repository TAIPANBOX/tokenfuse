# TokenFuse 1.0.0

The money plane of the TAIPANBOX stack: a reverse proxy in front of one LLM
provider that reserves a budget per run before the call and settles it after,
answers `402` with a named reason when a run would overspend, and writes what
it saw to a Parquet trace and to the shared agent-event bus. Two wire doors,
Anthropic Messages and OpenAI chat completions, one process per upstream shape.

## What 1.0 promises

`compat/1.0.json`, rendered as `COMPATIBILITY.md` and held by
`scripts/compat-surface.sh` on every push: the two binaries, the sixteen
subcommands and flags, the two listen defaults, 83 `TOKENFUSE_*` environment
names, the gateway's ten routes, thirteen request headers and sixteen response
headers, the Cloud's 33 routes and five headers, the nine Breaker wire strings,
the nineteen agent-event types, the sixteen trace Parquet columns, the three
image names and the Python SDK's fifteen public names. A frozen name is not
removed or renamed within this major. What is additive (a new event type, a
new price-book model, a new column, a new subcommand) and what is experimental
(raft HA, WASM policies, APNs push, radar, the router's rule syntax) is written
in the same file. Support line: the newest minor gets every fix; the previous
minor gets security-relevant fixes for 90 days after the newer one is tagged.

## Proven, by the 1.0 proving run (estate-gates `PROVEN.md`, section "The 1.0 proving run")

Every row below ran on the `v0.5.0` or `v0.5.1` image or on the tree between
them; 1.0.0 changes no behaviour after `v0.5.1` and freezes what those rows
measured.

- **INS-1, R0.** The README's `docker run` of the tagged image on a machine that
  had only the previous tag: `/healthz` 200, a 0.02 USD run refused on its
  third call with `402 budget_exceeded`. The image answers `--version` with its
  tag and commit from `v0.5.1` on (tokenfuse#275, proven by that tag).
- **RUN-1, R2 on GCP and AWS.** A 0.0006 USD run against the real Anthropic
  API through the cluster gateway: ten calls at 0.000034, call eleven `402`
  with the wire body, `/v1/runs` and the ledger agreeing, the run sealed by the
  record plane.
- **RUN-1, R3.** Six upstreams through both doors from one gateway per
  upstream: Anthropic (Messages), Ollama (Messages and OpenAI), Gemini on
  Vertex, `gpt-oss` on Bedrock and OpenRouter (OpenAI): the same budget, the
  same `402`, the same event on the bus, every provider. The enforcement path
  is wire-shaped, not vendor-shaped.
- **RUN-2, R0.** The wrong door for the process's wire is refused
  `400 wire_mismatch` before anything is reserved; the right door on the same
  run still has its full budget.
- **RUN-3, R3.** Streaming settle on the Messages door equals the usage the
  provider reported to the microdollar; on the OpenAI door across four
  providers a stream with no usage block settled at zero on `v0.5.0` and settles
  on the pre-flight estimate from `v0.5.1` (tokenfuse#283, invariant 43).
- **RUN-5 and RUN-6, R0 then R1.** Hierarchical runs: a child is refused on
  its parent's budget; a call without `x-fuse-agent-id` under wardryx
  enforcement is `400 identity_required`. Shadow forwards and records the
  refusal it did not make (`x-fuse-would-block`, one `breaker_shadow` event,
  tokenfuse#278, invariant 42); enforce answers `402` on the same call.
- **FAIL-1, R2.** Provider errors mid-run (200, 429, 503, 529, 200 from an
  in-cluster stub): each forwarded at cost zero, spent unchanged, no
  double-settle, the run continued. **FAIL-3, R2.** SIGKILL of the gateway
  mid-stream: the client got a truncated stream, the container was ready again
  in 28 s, the ledger consistent. **FAIL-2, R0 then R1.** wardryx killed under
  a running gateway: fail-open forwards and records `dependency_failed`,
  fail-closed refuses; both failmodes on record.
- **UPG-1 and UPG-5, R1.** A trace written by `0.4.4` read by `0.5.0`:
  `outcomes` and `sql` identical to the microdollar, the columns the old writer
  lacked read as empty; a stack-single compose moved from the 0.x pins to the
  new ones in place, volumes kept.
- **INT-1, R0.** Nine framework recipes (LangChain, OpenAI Agents SDK,
  PydanticAI, CrewAI, AutoGen, Semantic Kernel, LiteLLM, Haystack, Claude Code)
  against Ollama through both doors: twelve door runs, twelve refusals.
  **INT-2, R0.** Claude Code itself pointed at the gateway by
  `ANTHROPIC_BASE_URL`, budgeted and refused on the wire. **INT-3, R0.** The MCP
  credential broker with wardryx `decide()` on `tools/call`: `shell_exec`
  refused with wardryx's reason.
- **INS-2 and INS-5 on the 1.0 set, R1 and R2 on GCP.** `stack-single` by its
  README one-liner on two fresh boxes and `stack-k8s` on a fresh five-node
  cluster, this gateway at `v0.5.1` in both: every installer check green, images
  pulled, nothing built.
- **SUP-1, R0.** The README's own verify block from a machine that built
  nothing: `cosign verify-blob` on `SHA256SUMS`, `sha256sum -c`, and
  `gh attestation verify` on a binary and on the four images, one flipped hex
  digit failing.

## Upgrade note, 0.4.x and 0.5.x to 1.0.0

Nothing to migrate. No header, route, variable name, default, exit code, wire
body or Parquet column changed between `v0.5.1` and `1.0.0`; the version is the
promise, not a feature. A trace written by any 0.4.x or 0.5.x gateway reads
under 1.0.0 (UPG-1 above measured 0.4.4 to 0.5.0, and the read schema is
append-only, invariant 6). The two behaviour changes since `v0.5.0` are already
in `v0.5.1` and are both corrections of a promise the README made: shadow mode
records the refusal it did not make (`x-fuse-would-block`, `breaker_shadow`),
and a 2xx with no usage block settles on the estimate rather than at zero.

Two things to check on the way in. There is no `:latest` tag since `v0.5.0`
(decision 10.26, route A): a deployment pins `ghcr.io/taipanbox/tokenfuse:v1.0.0`
and its control plane `tokenfuse-control-plane:v1.0.0`. And the client packages
version with the gateway (decision 10.20): PyPI `tokenfuse-sdk`, npm
`tokenfuse` and the `tokenfuse` crate are `1.0.0` with the same helpers as
`0.5.x`; nothing in them changed.

## Not in this release, said plainly

- Not audited, not battle-hardened; the README keeps saying so. Start in
  shadow mode.
- When wardryx is unreachable the gateway fails **open** by default
  (`TOKENFUSE_WARDRYX_FAILMODE=open`) and records `dependency_failed`; the
  stack's launchers set it closed. Both are on record (FAIL-2); the default is
  a stated decision, not an oversight.
- The response-side taint firewall does not run on the streaming path; only a
  buffered answer's tool-use is judged (docs/26 section 8). The `max_tokens`
  clamp that docs/02 ADR-4 describes does not exist.
- Three open money-path issues, none silent on the wire but all worth knowing
  before a bill is compared: tokenfuse#282 (cache writes with the 1-hour TTL
  priced at the 5-minute rate), #267 (OpenAI cached tokens priced twice) and
  #260 (a reachable upstream's 429 or 400 emits no agent-event).
- Raft HA is compiled out of every shipped image; the `/v1/chat/completions`
  door was proven on R0 and R3, on the clusters only the Messages door ran;
  UPG-1 read eight calls of trace, not a day; the recipes' CI matrix has not run.
