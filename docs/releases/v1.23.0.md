# TokenFuse 1.23.0

A minor release. A held MCP tool call now says why it was held, the injection detector sees Unicode tag characters and bidi isolates, and every refusal text is cleaned before a model reads it.

It covers everything merged since v1.22.0: pull request #512, which fixes the CI gates that read pipes, and pull request #513, which carries the broker and detector changes. Pull request #511 moved the README to v1.22.0 after that tag existed. `compat/1.0.json` and `components.json` do not change.

## Upgrade

Read this section before you change the image tag.

1. No migration. Change the image tag.
2. **The detector now fires on Unicode tag characters and bidi isolates.** A page that holds U+E0000 to U+E007F, or U+2066 to U+2069, raises `suspected_injection` (the `hidden_text` signal). Under enforce the firewall judges that run, so a run that reads such a page can lose tools it had before. Check the firewall mode before you upgrade, and expect more refusals on pages that hide text this way.
3. **A held tool call says why.** The `-32004` refusal now reads `requires approval (approval <id>) (<reason>)`, where the reason is the policy's own, cleaned and capped at 200 characters. The code and the approval id are unchanged. A client that matched the old text exactly must match the new one.
4. **A denied tool call's reason is cleaned the same way.** It is one line, free of control and hidden characters, and capped at 200 characters.
5. **Soft hyphens, Arabic letter marks and Mongolian vowel separators raise nothing on their own.** They are removed from every text a reader sees, but they do not fire the detector, because they occur in ordinary web and Arabic text.

## Security

- **Refusal texts are cleaned before they reach a model (#513).** The hold reason, the deny reason and the approval id pass one cleaner: control and hidden characters are removed, whitespace is collapsed, and the reason is capped. An approval id is kept only after cleaning, and is dropped when nothing is left.
- **Phrases split by a cleaned-only character are now found (#513).** A soft hyphen, Arabic letter mark or Mongolian vowel separator inside a word (`ig\u{ad}nore`) or between words (`ignore\u{ad}all`) used to hide a phrase from the patterns. Both readings are now checked, and the union is what the gate sees.
- **The detector fires on tag characters and bidi isolates (#513).** See Upgrade, item 2.
- **Excerpts never quote a spaced reading of a secret (#513).** Excerpts quote only the text with those characters removed, where DLP sees a secret split by a soft hyphen whole. A finding that appears only when they read as spaces keeps its signal, and its excerpt carries the fixed marker `[excerpt withheld: found with separators removed]` and no document text.

## Added

- **A hold says why (#513).** See Upgrade, item 3.

## Fixed

- **CI gates that read a pipe now see the pipes that end early (#512, invariant 145).** A grep at the end of a pipeline can leave before the producer finishes, and a gate that read that as success measured nothing. `scripts/no-reader-leaves-a-pipe-early.sh` checks for it, and `scripts/gates-have-teeth.sh` plants the fault to prove the check fires.
