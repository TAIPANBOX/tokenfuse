# TokenFuse 1.12.0

An agent's memory is now judged as untrusted context, the gateway names each tool it
cannot classify, the compliance catalog cites the OWASP MCP Top 10, and nine security
switches that read a mistyped value as a weaker mode now refuse to start.

- A run whose prompt holds the agent's memory is judged like a run that read a web
  page: under the starter policy it cannot then run a command, write, or send.
- The first time the gateway sees a tool it cannot classify, it writes one warning
  naming the tool and the file to classify it in.
- Nine environment switches (DLP, PII, MCP scan, taint and Wardryx fail modes, the
  Wardryx mode, two broker requirements) exit 2 at start on a value they cannot read,
  where each used to start in its weaker mode.

Nothing is renamed or removed, no environment name is added, and nothing frozen in
`compat/1.0.json` moves. The umbrella crate and both client SDKs move to 1.12.0 with
no client behavior change.

## Added

- **Memory is untrusted context (#411, invariant 95).** A new firewall label,
  `memory`, reaches a run two ways: the built-in source map labels the output of
  Engram's MCP tools `recall` and `why` as `memory`, and a framework that puts memory
  into the prompt itself declares it with the existing `x-fuse-taint: memory` header.
  The starter rule `no-exec-after-untrusted` now lists `memory`, so a run carrying it
  cannot then exec, write or reach the network. A policy file replaces the starter
  policy, so when a file has no rule that reads `memory`, enforce mode adds one floor
  rule, `no-action-after-memory`, the same shape as the injection floor. An operator
  rule that names `memory` wins and no floor is added. Shadow mode records the label
  and refuses nothing.
- **An unclassified tool is named in the log, once (#411, invariant 96).** The
  starter policy already treated the output of any tool the source map does not name
  as `unclassified`, and the refusal said only that. The gateway now writes one
  warning the first time it sees each such tool, naming the tool and
  `TOKENFUSE_FIREWALL_CONFIG`, the file to classify it in. The list of names is capped
  at 256 per process, past the cap one line says the list is cut, and a name is cut to
  128 characters before it is logged. Mode `off` names nothing.
- **OWASP MCP Top 10 rows in the compliance catalog (#412, invariant 97).** The
  framework `OWASP-MCP-2025` (items MCP01 to MCP10, read from the OWASP project
  repository) is cited where a test in this repository holds the control:
  cross-references on `TF.MCP.POISON`, `TF.MCP.RUGPULL`, `TF.TAINT` and `TF.AUDIT`, each
  keeping its grade, and two new rows graded Partial because their limits are real:
  `TF.MCP.AUTH` (the broker's doors are opt-in and open on loopback when nothing is
  configured) and `TF.MCP.SCOPE` (secret scopes are opt-in, and an unscoped secret
  resolves for any agent). MCP04 (supply chain), MCP05 (command injection) and MCP09
  (shadow servers) are not claimed, and a test holds that no control cites them.

## Fixed

- **A mistyped security switch refuses to start (#413, invariant 98).** Each of these
  read a value it did not know as its weaker mode, without a word. Each now accepts
  its words in any case, ignoring surrounding spaces, keeps its default when unset or
  empty, and exits 2 before the listener binds on anything else, with one line naming
  the variable, the value and the accepted words.

  | Variable | Accepted words | A mistyped value used to mean | Process |
  |---|---|---|---|
  | `TOKENFUSE_DLP_PII` | off, shadow, mask, block | off | serve |
  | `TOKENFUSE_MCP_DLP_PII` | off, shadow, mask, block | off | mcp-broker |
  | `TOKENFUSE_MCP_DLP` | off, shadow, block | shadow | mcp-broker |
  | `TOKENFUSE_MCP_SCAN` | off, warn, block | warn | mcp-broker |
  | `TOKENFUSE_MCP_TAINT_FAILMODE` | open, closed | open | mcp-broker |
  | `TOKENFUSE_WARDRYX_MODE` | off, shadow, enforce | off | both |
  | `TOKENFUSE_WARDRYX_FAILMODE` | open, closed | open | both |
  | `TOKENFUSE_MCP_REQUIRE_PROOF` | 0, false, 1, true | off | mcp-broker |
  | `TOKENFUSE_MCP_REQUIRE_SECRET_SCOPES` | 0, false, 1, true | off | mcp-broker |

  The cache and tools-prune switches (`TOKENFUSE_CACHE`, `TOKENFUSE_TOOLS_PRUNE`) are
  measurement toggles and keep an unknown value as off with one warning, by decision.

## Upgrade

- **A deployment with a value outside the accepted words in any switch above now
  refuses to start** (exit 2) where it used to start in the weaker mode. Fix the
  value. A word in capitals now means what it spells: `TOKENFUSE_WARDRYX_MODE=ENFORCE`
  turns enforcement on where it used to leave it silently off.
- **The two broker requirements no longer read `yes`, `on` or `no`.** Those were read
  as off; they are refused now. Use `1` or `true` to require, `0` or `false` to say off.
- **A policy file with no rule naming `memory` gets the floor in enforce mode.** Before
  this release the output of `recall` and `why` was `unclassified`, which a policy file
  could leave unmentioned; it is now `memory`, and a run carrying it cannot then exec,
  write or reach the network unless the file says otherwise in a rule that names
  `memory`.
- **The launchers write only accepted words.** stack-single and stack-k8s pin
  TokenFuse 1.11.0 and are unaffected until their pin moves; stack-up builds TokenFuse
  from source, so it takes this release with the next build. All three set these
  switches only to accepted words (`shadow`, `off`, `enforce`, `closed`), so each
  starts with the values it writes today. A value an operator passes through to them
  is read by the new rule.

## Not proven

- No live gateway, broker or provider was run with this release. The behavior was
  measured by tests through CI, including tests that start the real binary with a
  mistyped switch (one per process) and assert it never serves.
- The `memory` label is only as good as the source map. A framework that recalls
  memory through a tool the map does not name is `unclassified`, which the starter
  rule already refuses and which is now named in the log. Nothing tells a memory the
  user wrote from one the agent wrote.
- The list of unclassified names lives in memory: a restarted gateway names each tool
  again, once, and each gateway keeps its own list.
- Each OWASP MCP cross-reference is a claim a reader can check against the named test,
  not a mechanical proof. owasp.org was unreachable from the build machine that day,
  so the list was read from the OWASP project repository.
- Found and not changed, for a decision of their own: a set `TOKENFUSE_MCP_LOCK` path
  that cannot be read still means no rug-pull baseline, without a refusal; and a
  half-set cluster TLS pair reads as plaintext, in the `cluster` feature that no
  shipped image builds.
