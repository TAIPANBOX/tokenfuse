# TokenFuse 1.9.0

A call the provider may have billed, but the gateway could not settle, is no
longer forgotten and can now be closed by a person with evidence.
- A retained reservation survives a restart: with `TOKENFUSE_DATA_DIR` set, the
  gateway journals it and puts it back at startup, on its original window and
  run chain.
- A gateway refuses to start on a retained journal it cannot read, rather than
  serving as if nothing were owed.
- An admin can close a retained reservation with evidence, carrying a
  short-lived token the operator console mints after a passkey assertion. The
  closure is off unless `TOKENFUSE_CLOSURE_SECRET` is set.
- An observed closure reaches the Cloud the way a settled call does, so after a
  restart the run and unit seeds include it.

This is a minor release because it adds two gateway routes,
`POST /v1/retained/close` and `GET /v1/retained` (behind the admin keys, and
present only when `TOKENFUSE_CLOSURE_SECRET` is set), and one environment name
behind that feature. Nothing is renamed or removed, and nothing frozen in
`compat/1.0.json` moves. The umbrella crate and both client SDKs move to 1.9.0
with no client behavior change.

## Added

- **A retained reservation survives a restart (#390, invariant 88).**
  - **The gap.** A call handed to the provider that ended before any answer is
    retained (invariant 50): its run and unit reservations stay outstanding.
    That liability lived only in the process, so a restart forgot it and the
    next call was admitted against room the provider may already have billed.
  - **The change.** With `TOKENFUSE_DATA_DIR` set, the gateway appends each
    retained reservation to `retained-reservations.ndjson` and syncs it, then
    replays the file before the listener binds. A run comes back at the
    generations its chain names; a unit half comes back only in its own month.
    Liability comes from the journal alone, never from settled spend. Without
    `TOKENFUSE_DATA_DIR` nothing changes.
- **A retained reservation can be closed with evidence (#394, invariant 89).**
  - `POST /v1/retained/close` and `GET /v1/retained`, behind the admin keys,
    registered only when `TOKENFUSE_CLOSURE_SECRET` is set (at least 32 bytes;
    a shorter one stops the gateway with exit 2).
  - The request carries a token in `x-fuse-closure-token`, minted by the
    operator console after a passkey assertion and bound to one reservation
    and its revision, for at most 300 seconds.
  - `observed` settles at the cost the evidence gives and `no_charge` releases
    at zero, on the run chain and the unit, exactly once. The same operation
    retried answers the recorded result; the same operation with different
    content is a conflict that changes nothing.
  - The closure is written to the journal and synced before any money moves,
    and at startup the journal is rewritten with only the records still open.
- **An observed closure reaches the Cloud (#395).** It writes one `allow` row
  through the same sink as a settled call, so in Cloud mode the run and unit
  seeds include it after a restart. A `no_charge` closure writes none, and a
  replayed operation writes no second row.

## Fixed

- **A parent restored from the journal is given its Cloud budget (#391).**
  Restored runs came back at budget zero, and a parent whose budget lives in
  the Cloud refused every new child call with 402 until it called itself. It
  now gets its Cloud budget on its next child's call, as an unopened parent
  does.
- **An unreadable journal stops the gateway (#392, #393).** A journal that
  exists and cannot be opened or read now ends the start with exit 2 and a
  line naming the path and the error. Serving without it would admit calls
  against the liability it holds. A missing or empty journal still starts
  cleanly. The line says to fix the file, because moving it away starts the
  gateway with none of what it holds.
- **The Cloud no longer accepts a fallback credential (#380).** The fixed
  development key is gone. `TOKENFUSE_CLOUD_ALLOW_DEVKEY` stays a frozen name,
  and setting it now stops the control plane at start rather than accepting a
  public key as admin.
- **The demo compose stack reaches its control plane on loopback with keys
  from the environment, and pins released images (#384, #386).**

## Upgrade

- Nothing is needed for an existing deployment: the journal is written only
  with `TOKENFUSE_DATA_DIR`, and closing is off without
  `TOKENFUSE_CLOSURE_SECRET`.
- If `TOKENFUSE_CLOUD_ALLOW_DEVKEY` is set anywhere, unset it and set real keys
  in `TOKENFUSE_CLOUD_KEYS` before upgrading the control plane.
- Closing needs the same secret on the gateway and in the console, with no
  trailing newline on either side: the console trims whitespace from its file
  and the gateway reads the variable as given. The launchers write it that way.

## Not proven

- No closure has been run against a live provider bill.
- Power-loss durability of the journal was not measured, and macOS `fsync` was
  not checked for full durability.
- Two gateways sharing one data directory are not supported.
- An observed closure's row is filed under the leaf run only, so an ancestor's
  Cloud figure omits it; it counts as one more call and its FOCUS row reads
  `estimated`.
- No agent event describes a closure yet. The audit is the journal's closure
  line, the gateway's log line and the console's own command chain.
