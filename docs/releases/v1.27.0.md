# TokenFuse 1.27.0

A minor release. It adds per-key rate and concurrency limits, two new agent-event types, an incident for a provider that refuses the gateway's credential, a credential of its own for each MCP upstream, a delegated path from a child run into a parent run another agent owns, and sampling of the cache walk in shadow mode.

The release covers everything merged since v1.26.0: pull requests #537 to #542 and the commits they carry.

## Upgrade

1. Change the image tag.
2. Per-key limits are off by default (#541). Once `TOKENFUSE_KEY_RPS`, `TOKENFUSE_KEY_BURST` or `TOKENFUSE_KEY_CONCURRENCY` is set, a call over the limit gets `429` with `Retry-After` and `{"error":{"type":"rate_limited",...}}`. Clients should retry after the stated delay. If any of these variables holds a value the gateway cannot read, the gateway stops before it listens.
3. Two new agent-event types appear on the bus: `rate_limited` (medium) and `price_fallback` (low) (#542). A consumer that reads events strictly must accept both. They are registered in agent-passport SPEC 6.2. `contracts/tokenfuse-constants.json` now lists 25 event types. `GET /v1/price-book` adds `fallback_events_unreported`.
4. In shadow mode, the semantic cache walks only one in ten of the lookups that the exact index did not answer (#539). A shadow would-hit rate is therefore a sampled estimate. `TOKENFUSE_CACHE_SHADOW_SAMPLE_EVERY=1` restores a walk on every lookup. Mode `on` is unchanged.
5. Order of refusals on a call that names a parent run (#537):
   - A refusal for the agent id, for the chain cap or for a bad delegation now comes before `parent_owned_elsewhere`, `seed_pending` and the budget errors.
   - A delegation proof is spent even when the call is then refused, including `503 seed_pending`. A client that retries must sign a fresh proof.

## Security

- **Per-key rate and concurrency limits (invariant 148, #541).** The limits are keyed on the principal the door verified: `key:<id>` for a client key, `tok:<agent>` for an agent token, or one shared bucket when nothing authenticates. A call is refused before anything is reserved. A concurrency refusal takes nothing from the rate bucket, and a call refused on rate is not counted as in flight. The MCP broker is not bounded by these limits.
- **Delegated parent runs for agent tokens (invariant 120, #537).** A call that an agent token admitted may roll up into a parent run owned by another agent token only when the person's delegation proves a chain that names the parent's agent. A claimed chain is refused, and so are a static key, a parent owned by a key, and a near match of the owner's agent. Every run above the parent is judged by the same rule, up to the ledger's depth of 64. A lineage cut off at that depth is refused.
- **Each MCP upstream gets its own credential (#538, tokenfuse#364).** `TOKENFUSE_MCP_UPSTREAM_CREDENTIALS` maps each upstream (`default` for `TOKENFUSE_MCP_UPSTREAM`) to a mounted file, and the first line of that file is a bearer token. The broker sends the token to that upstream as `Authorization: Bearer`; the caller's own credential is never sent. If any entry is bad, the broker stops at start and names the file, never the token.

## Observability

- **A provider that refuses the gateway's credential becomes one incident per caller (invariant 149, #540, tokenfuse#312).** The gateway counts a provider's `401` and `403` answers by caller, separately from the provider's health, and sends them in its provider-failure report. Three refusals within ten minutes open one `provider_auth_refused` incident in the console at `medium`. When the incident opens, one `dependency_failed` event goes on the bus under the agent. A refusal with no agent appears on the console only.
- **`rate_limited` (medium, #542)** is written for a per-key `429`, at most once per principal per minute; the refusals in between are counted in `unreported_since_last`. Both the throttle and the event's subject come from the credential, never from a header, and the event names no run.
- **`price_fallback` (low, #542)** is written once per model per process when a call is priced at the fallback rates, at most 60 times a minute per gateway. A call that names no agent writes no event and is counted on `GET /v1/price-book`.

## Performance

- **Shadow sampling of the cache walk (#539, tokenfuse#329).** Under varied traffic, almost every shadow lookup fell through to the similarity walk. The walk is now sampled (see Upgrade). An exact repeat is never sampled, and `put` is unchanged.
