# TokenFuse 1.18.0

A minor release. The agent-event stream can now be signed with checkpoints that keyryx custody certifies, the cloud's audit manifest can be signed through keyryx, and the MCP broker refuses to start in one configuration it used to start in. The image signature changes format.

It covers everything merged since v1.17.0: pull requests #460 (the v1.17.0 badge, README examples and compose pins), #461, #462 and #463.

This is a minor, not a patch: it adds a variable set that is read only when switched on, and it changes one startup. No frozen name in `compat/1.0.json` is removed or renamed.

## Added

- **Signed checkpoints of the agent-event stream (#461, invariant 128).** Off unless `TOKENFUSE_CHECKPOINTS_DIR` is set. When it is, the gateway writes a checkpoint beside each event stream, following SPEC 6.5.1 version 1. The checkpoint is signed with a key keyryx custody certifies for this name, so a reader can check the stream's bytes without trusting the file. The key is named by `TOKENFUSE_CHECKPOINT_KEY_NAME`, and its lifetime by `TOKENFUSE_CHECKPOINT_KEY_LIFETIME_SECS` (default 86400).
- **Audit manifests signed through keyryx (#462, invariant 130).** `TOKENFUSE_CLOUD_AUDIT_SIGNER=keyryx` makes keyryx custody sign the cloud's audit manifest, with `TOKENFUSE_CLOUD_AUDIT_KEYRYX_URL`, `TOKENFUSE_CLOUD_AUDIT_KEYRYX_KEY` and `TOKENFUSE_CLOUD_AUDIT_KEYRYX_CREDENTIAL_FILE`. The manifest names the key id keyryx signed with, so an auditor can find the same key in keyryx's key set. A manifest keyryx did not sign is never served: an unreachable or refusing keyryx answers 503. The in-process signer is unchanged.

## Breaking

1. **The MCP broker refuses to start with agent tokens on and a taint gateway named, unless it holds a key of its own (#462, invariant 129).** With `TOKENFUSE_AGENT_TOKENS` on and `TOKENFUSE_MCP_TAINT_GATEWAY` set, a broker that has no `TOKENFUSE_MCP_TAINT_GATEWAY_KEY_FILE` exits 2 before its listener binds. It used to start. Every call an agent token admitted then reached the taint gateway with no credential: a gateway with client keys answered 401, and `TOKENFUSE_MCP_TAINT_FAILMODE` (open by default) decided the call with nothing judging it.

## Migration

- **Taint gateway (#462).** Set `TOKENFUSE_MCP_TAINT_GATEWAY_KEY_FILE` to a file holding the broker's key, whose key id is `broker` in the gateway's `TOKENFUSE_CLIENT_KEYS`. Or unset `TOKENFUSE_MCP_TAINT_GATEWAY`, if no taint gateway should be consulted.
- **Checkpoints (#461).** Nothing to do unless you set `TOKENFUSE_CHECKPOINTS_DIR`. Then `TOKENFUSE_CHECKPOINT_KEYRYX_URL`, `TOKENFUSE_CHECKPOINT_KEYRYX_CONSUMER`, `TOKENFUSE_CHECKPOINT_KEYRYX_CREDENTIAL_FILE` and `TOKENFUSE_CHECKPOINT_KEY_NAME` must all be set, or the gateway refuses to start.
- **Cloud audit signer (#462).** Nothing to do unless you set `TOKENFUSE_CLOUD_AUDIT_SIGNER=keyryx`. Then the three keyryx variables above are required. Setting `TOKENFUSE_CLOUD_AUDIT_SIGNING_KEY` beside it is refused at startup.

## Upgrade

Replace the image tag with `v1.18.0`, or use the release binary. Before the upgrade, check each deployment against the Breaking item above.

- An MCP broker with agent tokens on, a taint gateway named and no `TOKENFUSE_MCP_TAINT_GATEWAY_KEY_FILE` exits at startup, with a message that names that variable.
- The image signature is now written in cosign's legacy `.sig` format (#463), because policy-controller v0.15.1 reads only that format. A verification step that requires the bundle format must accept the legacy one.
