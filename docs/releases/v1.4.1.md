# TokenFuse 1.4.1

Two fixes found on the 2026-09-27 lab runs, one of them a credential that left
the gateway, and a flaky test that turned out to be a real ordering race.
Nothing on the wire changes. The umbrella crate and both client SDKs move to
1.4.1 with no client behavior change.

## Fixed

- **A delegation credential never reaches the provider (#345, invariant 69).**
  A caller proving a vouchryx delegation sends `Authorization: DPoP <token>`.
  The gateway verified it and then forwarded the same header upstream, because
  its header allowlist carries `authorization` for the OpenAI door's own
  pass-through provider key. So the provider received the delegation token (it
  answered "Invalid bearer token"). A `DPoP` scheme is now never forwarded,
  whether or not the gateway resolved it, on both doors; a pass-through
  `Authorization: Bearer <provider key>` is unchanged. Tests red first on 1.4.0,
  and two planted mutants ("forward regardless", "strip on one door only") each
  caught.
- **A restarted gateway remembers what a run has already spent (#346,
  invariant 70).** The per-run spend ledger lived in memory and restarted at
  zero, while the Cloud kept the month. Measured: a run at 109% of its Cloud
  budget kept answering after a restart, and a later refusal quoted only the
  spend since that restart. At startup, before serving, the gateway now reads
  each run's spend from the Cloud (`/v1/runs`, the last 31 days, bounded like
  the unit seed) and credits it once, the moment the run is first opened, so
  the first call after a restart is checked against the true figure. Review
  closed a race in the first version, where the seed could be dropped when two
  first requests for one run arrived together. Five mutants planted, each
  caught.
- **Telemetry queued behind a drain is not overtaken by a fresh send (#347,
  invariant 71).** During an outage, a new batch could be sent on its own
  while the drain was mid-retry and land at the Cloud ahead of older records.
  It now queues behind the drain. This was a CI flake
  (`the_cap_drops_the_oldest_and_says_so_once`); the sink tests that can write
  the outage line now all hold the log lock, which a second flake pointed at.

## Upgrade

Nothing to change. A gateway with a Cloud URL and key seeds run spend on its
own at startup; one without them behaves as before.

## Not proven

The seed was proven by tests and not yet by a restart on a live cluster. A run
quiet for more than 31 days, or closed and reopened within one process, starts
from zero, as named in invariant 70.
