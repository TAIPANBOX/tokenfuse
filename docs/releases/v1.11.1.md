# TokenFuse 1.11.1

A firewall mode the gateway cannot read now stops it from starting, instead of
running a firewall that refuses nothing.
- `TOKENFUSE_FIREWALL` accepts `off`, `shadow` and `enforce` in any case. Any
  other value exits 2 before the listener binds, with one line naming the
  variable, the value and the three accepted words.
- Unset or empty is unchanged: no override, so the mode is the policy file's or
  the default, `shadow`.

This is a patch release: it fixes how one existing variable is read. Nothing is
renamed or removed, no environment name is added, and nothing frozen in
`compat/1.0.json` moves. The umbrella crate and both client SDKs move to
1.11.1 with no client behavior change.

## Fixed

- **A mistyped `TOKENFUSE_FIREWALL` refuses to start (#408, invariant 94).**
  The variable was matched against the exact lowercase words, and any other
  value was ignored without a word, so `enfroce`, `Enforce` or `ENFORCE`
  started a gateway in the default mode while its operator believed it
  enforced. It is now read the way `TOKENFUSE_MODE` has been read since
  invariant 72: the three words in any case are honoured, anything else is
  refused at start. A valid value still overrides a policy file's `mode`.
  Found while the launchers were moved to `enforce`; each of them already
  refuses such a value before it starts the gateway.
- A comment in `main.rs` said the firewall's default was `off`; it has been
  `shadow` since invariant 26.

## Upgrade

- **A deployment whose `TOKENFUSE_FIREWALL` holds a value outside the three
  words now refuses to start** (exit 2), where it used to start in shadow or at
  the policy file's mode. Fix the value; `Enforce` and `ENFORCE` are accepted
  as `enforce`.
- **Nothing else to configure.** stack-single v1.1.29, stack-k8s v1.1.41 and
  stack-up already validate the word themselves and set `enforce` by default.

## Not proven

- No live gateway, broker or provider was run with this release; the refusal
  was measured by tests through CI, including one that starts the real binary
  with a misspelt value and asserts it never serves.
- The MCP broker reads no firewall mode, so a bad value does not stop it.
