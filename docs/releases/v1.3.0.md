# TokenFuse 1.3.0

This release lets the Cloud tell a quiet site from a dead one. Since 1.2.0 the
Cloud shows each site's last push on `GET /v1/gateways`, but a gateway only
pushed when it had records, so a healthy site with no traffic went silent
exactly like one that had died (#296). The gateway now sends a heartbeat when
it has had nothing to say for a while. The Cloud does not change; it already
read an empty push as a heartbeat. The frozen names in `compat/1.0.json` do
not change; this release adds one setting, which is why it is a minor. The
umbrella crate and both client SDKs move to 1.3.0 with no client behavior
change.

## Added

- **An idle gateway heartbeats the Cloud (#337, invariant 66).** When
  nothing has reached the Cloud for `TOKENFUSE_CLOUD_HEARTBEAT_SECONDS`
  (default 30), the gateway POSTs `{"records": []}` to `/v1/ingest` with its
  own key, so `last_push_millis` keeps moving while the site is up. Any
  answer from the Cloud resets the clock, a real push or a replay as much as
  a heartbeat, so a busy gateway sends none. `0` turns it off. A value that
  is not a non-negative integer means the default, with one warning; 1 to 4
  are raised to 5, with the same warning.
- **A heartbeat is never queued and never replayed.** A replay after an
  outage would make a site that was down look alive in the past, so a
  failed heartbeat is simply lost. None is sent while the retry queue is
  draining, because the drain already shows the site is there. A refused
  heartbeat warns once per status, like any refused push.

## Measured

On 2026-09-27 a hub on GCP and a site at home, the site idle, the hub's
`GET /v1/gateways` sampled every 30 seconds: without the heartbeat the
site's last push aged from 34 to 286 seconds in four minutes; with it, one
push every 31 seconds or so and a last push never older than 22 seconds.
That run also caught a first version that pushed only every other interval;
the release carries the fix and a test that fails without it.

## Upgrade

Nothing to change. A gateway with `TOKENFUSE_CLOUD_URL` set starts sending
heartbeats at the default interval; set
`TOKENFUSE_CLOUD_HEARTBEAT_SECONDS=0` to keep the old behavior.

## Not in this release, said plainly

- A site that goes silent is visible on `/v1/gateways` and on the dashboard,
  and still raises no incident or agent-event.
- A heartbeat proves the gateway process and its network path to the Cloud,
  not that the agents behind it are doing useful work.
- A site that dies looks alive for up to one interval.
