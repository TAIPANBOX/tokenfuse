# TokenFuse 1.0.2

Three corrections on the delegation and money paths, each a defect that was
silent: a revocation that did not match, a revocation list that could be
emptied by a malformed answer, and a ledger that admitted spend against a
parent it had never opened. No name, default, route or wire body of
`compat/1.0.json` changes. Reviewed as T3 changes (a second model read every
diff before it was pushed, twice for the ledger).

## Fixed

- **A subject revocation never matched an agent inside a human-rooted token**
  (tokenfuse#298, twin of agent-stack-go#61). Both doors asked the revocation
  list about the token's `sub`, the person at the root, while the README and
  the feature file revoke the AGENT by subject; a compromised agent named in
  `act` matched nothing. `verify_delegation` now reads the chain first and asks
  once per entry, root first, first hit refuses; at most `MAX_CHAIN_ENTRIES`
  calls, none for a token that failed earlier; the gateway hook warns once per
  request on a fail-mode fallback. Invariant 48.
- **A revocation snapshot with no `revocations` array was read as an empty
  list** (tokenfuse#299, twin of the 2026-09-17 review's F4). A body silent
  about the member, or naming it `null`, parsed as an empty list, `install`
  accepted it as fresher, and every held revocation was gone; a wrong upstream
  or a proxy in the way was enough. Such a body is now a parse error and a
  failed poll (the held list stays, ageing), and an entry that is not a JSON
  object is refused the same way. Invariant 32.
- **A child run naming a parent this gateway had not opened was checked
  against nothing** (tokenfuse#300, found by the second-model pass over the
  2026-09-17 money-path review; the review's F01, F02 and F09 close with it).
  The walk up the parent chain stopped silently at a missing parent, at 64
  ancestors, and `settle` walked the live tree again, so a parent that appeared
  between reserve and settle had another call's reservation released against
  it. A `Reservation` now carries the chain it was admitted against and settles
  on that chain exactly once; an unopened parent, a chain past the cap and a
  closed run are refusals; a parent may be adopted only before any admission
  on the run or a descendant; `Microusd::checked_add` in every admission
  predicate, so a saturated sum reads as exceeded. Invariant 49.

## What to know on the way in

- The version is the promise: nothing in `COMPATIBILITY.md` moves. The client
  packages version with the gateway and are 1.0.2 with no change in them.
- **Orchestrators whose workers call first.** In enforce mode a call carrying
  `x-fuse-parent-run-id` for a run this gateway has not seen is refused with
  the existing `402 budget_exceeded` and a detail naming the parent, unless an
  operator set a Cloud budget for that parent id, which opens it on first
  sight. Have the coordinator make its first call before its workers, or set
  its budget in the Cloud. Shadow and warn forward and record the would-block.
- **A run keeps the parent it was opened with.** A later call that declares a
  different parent, or declares one after the run has reserved, is refused
  with `400 invalid_request` (`code`: `parent_run_changed`,
  `parent_adopted_too_late`, `parent_is_self`); every trace row carries the
  parent the ledger holds, never the header. A 400 is not a money refusal: no
  row, no event.
- **`TOKENFUSE_DELEGATION_REVOCATIONS` deployments**: a feed that answers a body
  with no `revocations` array now fails the first fetch at startup (exit 2) or
  is a logged failed poll afterwards, never an installed empty list.
- The raft (cluster) build keeps its older ledger semantics behind the same
  trait; invariant 49 lists what it does not hold. HA is compiled out of every
  shipped image.

## Proven

- Every fix red first on the unfixed tree, then green: seven of the review's
  own probes and three written for the missed items, all red at `80e0d42`;
  fourteen mutants on the ledger, one on the snapshot parser, each caught by a
  named test. 1278 tests, 223 scenarios bound, `gates-have-teeth.sh` 57 cases.
- Not proven: restart durability (a restarted gateway forgets every run and
  reservation; issue #293), the raft backend's parity with the in-process
  ledger, and PR 2's ground (a reservation leaked when a call is cancelled
  before the provider answers).
