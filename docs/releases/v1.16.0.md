# TokenFuse 1.16.0

A minor release that closes four defects on the gateway's request path. A run belongs to the principal that opened it. A read tool carries no data out after private input. The gateway can hold its own provider key, so a caller's provider credential never leaves the process. An agent's own short-lived token is its door credential at every door, and the agent and its unit come from that token instead of from a header. The policy plane is also told how the gateway knew the agent.

It covers everything merged since v1.15.0: pull requests #450, #451, #452 and #453. Two of them add a credential an operator configures, and two change what a call is judged on when client keys are configured or a read tool is used. The **Breaking** and **Migration** sections say which deployments are affected. Read them before upgrading.

This is a minor, not a major: no frozen name in `compat/1.0.json` is removed or renamed. The changes alter who may name a run, what a read tool may carry, which credential reaches the provider, and how an agent is identified. They do not alter the names of the surface.

## Added

- **The gateway can hold its provider key (invariant 122, #452).** `TOKENFUSE_UPSTREAM_KEY_FILE` names a file holding the provider key, read once at startup. `TOKENFUSE_UPSTREAM_AUTH` (`x-api-key` or `bearer`) names the header the key is sent in; unset, the Anthropic door sends `x-api-key` and the OpenAI door sends `Authorization: Bearer`. A gateway without the file forwards as before and says so at startup and on `GET /healthz?detail=1`.
- **An agent's own token is its door credential (invariant 123, #453).** `TOKENFUSE_AGENT_TOKENS` is `off` (the default, nothing changes), `accept` (a token is accepted beside every static key) or `require` (every static key is refused with `401 agent_token_required`). A token is an access token vouchryx minted for one enrolled agent. It is verified offline and must be presented with a proof of possession for its key. The LLM doors and the MCP broker both read it. A process that turns the switch on without the delegation door's issuer, key set, origin, a non-empty audience and a revocation list refuses to start.
- **The policy plane is told how the gateway knew the agent (invariant 124, #453).** The decision request carries `identity_source`: `agent-token` for a call an agent token admitted, `client-key` for a static key, and `none` with client authentication off. wardryx reads it through a `require_identity_source` rule. An older wardryx ignores the member.
- **Run owners survive a restart (invariant 120, #450).** With `TOKENFUSE_DATA_DIR` set and client keys on, each run's owner is appended to `run-owners.ndjson` in that directory and synced before the call that claimed the run goes on. It is replayed at startup. A file that exists but cannot be read stops the gateway (exit 2) before it listens.

## Fixed

- **A run belongs to the principal that opened it (invariant 120, #450).** With client keys configured, a key that names a run another key opened is refused `403 identity_mismatch` with reason `run_owned_elsewhere`. The refusal carries no labels and no budget figure. A child run that names another key's run as its parent is refused with `parent_owned_elsewhere`, and inherits nothing. Both refusals are put on the bus. The tool-call check and the metered routes now agree about who owns a run.
- **A read tool carries no data out after private input (invariant 121, #451).** `fetch_url`, `browse` and `web_search` are network reads. After a secret, the starter policy refuses them. After a file, an email or a memory, a read is refused when its arguments carry a secret, carry PII while PII blocks, carry a path or query of 512 bytes or more, carry a run of 64 base64-alphabet characters, or carry more than 8 parameters. `remember` is a write. An enforce-mode policy file that denies no `unclassified` capability gets the unmapped-tool floor.
- **A caller's provider credential does not reach the provider when the gateway holds the key (invariant 122, #452).** With the key held, a caller's own `x-api-key` or `Authorization` that is not a gateway credential is refused `401 provider_credential_refused` before anything is reserved or forwarded. The refusal puts one `identity_mismatch` on the bus that names the header and never the credential.

## Breaking

Each item says what changes for an existing deployment. Items 2 and 4 apply only when the operator sets the variable named.

1. **Run ownership with client keys on (#450).** Two keys that share a run id, or a worker key that names a coordinator key's run in `x-fuse-parent-run-id`, now get `403 identity_mismatch`. Without client keys nothing changes.
2. **A held provider key refuses a caller's own provider key (#452, only with `TOKENFUSE_UPSTREAM_KEY_FILE` set).** A caller that still sends its own provider key gets `401 provider_credential_refused`. An auth word without a key file, or a key file without `TOKENFUSE_UPSTREAM`, refuses to start (exit 2).
3. **Read tools after private input (#451).** After a secret, `fetch_url`, `browse` and `web_search` are refused by anti-exfiltration. After a file, an email or a memory, a read whose arguments carry private data is refused. `remember` after untrusted input is refused. `http_get` and `fetch` are not named in either firewall map, so they are unclassified: after untrusted input they are refused as before, and after a secret alone no rule refuses them. An enforce-mode operator file that names no rule denying `unclassified` now refuses an unmapped tool after untrusted input.
4. **Agent tokens (#453).** Even with `TOKENFUSE_AGENT_TOKENS` off, an `at+jwt` access token presented as a delegation chain is refused. vouchryx began minting that type on 2026-10-18, and no client presented one before. With the switch on as `accept`, a delegation proof is single-use, and when it carries `ath` it must name the token it came with. With `require`, every static key is refused.

## Migration

- **Run ownership (#450).** Give each key its own run ids. To let a worker key run under a coordinator's run, list the worker's key id under `may_parent` in the coordinator's key entry in the identity map (`keys[]`). The list is one way and takes literal key ids only. Before the upgrade, check that no two keys share a run id in your own logs. With `TOKENFUSE_DATA_DIR` set, read `run-owners.ndjson` before you move it aside, because a file that cannot be read stops the gateway.
- **A held provider key (#452).** Set `TOKENFUSE_UPSTREAM_KEY_FILE` to a file the gateway can read, and `TOKENFUSE_UPSTREAM_AUTH` if the default header is wrong for your SDK. Turn client keys on first: with no client keys there is no gateway credential, so every provider credential a caller sends is refused. Point each SDK at its gateway key, sent as `x-fuse-key`, or as `x-api-key` or `Authorization: Bearer` when no `x-fuse-key` is sent.
- **Read tools (#451).** Classify your tools in a `TOKENFUSE_FIREWALL_CONFIG` file, as a source or as a capability. Run the firewall in shadow first and read the `taint_shadow` events. A read that is refused for private data and should not be needs its arguments changed, or a rule of your own, since the caps (512 bytes of path and query, 64 base64-alphabet characters, 8 parameters) are fixed in this release.
- **Agent tokens (#453).** Set `TOKENFUSE_AGENT_TOKENS=accept` with the delegation door configured: issuer, JWKS, origin, a non-empty `TOKENFUSE_DELEGATION_AUDIENCE` and `TOKENFUSE_DELEGATION_REVOCATIONS`, which fails closed. For the MCP broker, also set `TOKENFUSE_MCP_TAINT_GATEWAY_KEY_FILE` and add a `<secret>:broker` line to the gateway's `TOKENFUSE_CLIENT_KEYS`, so the broker can relay a token to the tool-call check. Move to `require` only when every agent holds a token. A wardryx rule that uses `require_identity_source` needs a wardryx that reads the member.

## Upgrade

Replace the image tag with `v1.16.0`, or use the release binary. Before the upgrade, check each deployment against the Breaking cases above. What an operator will see on upgrade:

- A gateway with client keys refuses a second key that names a run id the first key opened.
- A gateway that sets `TOKENFUSE_UPSTREAM_KEY_FILE` refuses a caller's own provider key with `401`.
- A read tool after private input is refused in enforce mode, and shows as `taint_block` on the bus.
- `GET /healthz?detail=1` carries a warning when the provider key is not held. Plain `/healthz` does not change.

The README examples, the release badge and the compose image pins move to `v1.16.0` in a follow-up change after the tag, as they did for v1.15.0, so this release changes no README or compose file.

## Not proven

- No live provider call and no live launcher were run. The tests drive the real binary and the real router against local stub upstreams, and the Rust build and test run is CI's.
- No live vouchryx token has reached the agent-token door. The tests mint tokens the way vouchryx mints them. The revocation latency, about one twelve-second poll, is designed and was not measured.
- The replay caches for agent-token proofs and the run-owner claims are per process. The JWKS is read at startup, so a key rotation needs a restart of each door.
- A delegation token alone is not a door credential. Under `require`, a delegated call still needs a client key.
- A first claim on a new run id and a second call of the same run by its owner can race. A crash in that window can lose the owner. A first key that names a run id before its real owner does takes the run, which costs the owner its checks and not its labels. Two gateways that share one data dir can replay their owners in different orders.
- The read rule judges the arguments of a buffered model tool call. A streamed tool call is judged on its name, because the stream hold keeps names only. The MCP broker's `tools/call` and the tool-call check receive no arguments.
- The cap values of the read rule are a choice, not a measurement. Coverage was not measured.
