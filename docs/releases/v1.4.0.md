# TokenFuse 1.4.0

Two fixes found on the 2026-09-27 lab runs: a call's cost now rounds toward the
safe side, and a delegation proof on the OpenAI door is checked against that
door's own path. A refused delegation proof also says what it is. It is a minor
because it adds one name on the wire (`delegation_refused`); nothing frozen in
`compat/1.0.json` moves. The umbrella crate and both client SDKs move to 1.4.0
with no client behavior change.

## Fixed

- **A call's cost rounds once, on the sum, toward over-charging (#341,
  invariant 67).** Each priced part was divided and rounded down on its own, so
  a call lost up to just under one micro-USD per part: a real `gpt-4o-mini`
  call of 13 input and 2 output tokens was charged 2 micro-USD where the price
  book gives 3.15. The parts are now summed exactly and the total rounds up
  once (that call is 4). Every figure the ledger, the Cloud and the budgets read
  comes from this one function.
- **A delegation proof on the OpenAI door is checked against that door (#342,
  invariant 68).** The DPoP `htu` the gateway required was fixed to
  `/v1/messages` on both doors, so on `/v1/chat/completions` a correct proof was
  refused and a proof naming the other door's path was accepted. Each door now
  requires its own path.

## Changed

- **A refused delegation proof answers by its own name (#342).** It was the
  client-credential `401`, whose text told the caller to send `x-fuse-key`,
  which was never the problem. It is now `401` with `type: delegation_refused`
  and a reason that names no cause, on the LLM doors and the MCP broker alike;
  the answer stays the same whatever the cause, so it tells a caller nothing
  about which check failed.
- **The operator's log names the cause.** A refused delegation token is logged
  with its precise reason (revoked, bad signature, expired and so on) instead of
  one `BadToken` for all of them, so a revocation working and a key mismatch no
  longer read alike. The token itself is never logged.

## Upgrade

Nothing to change. A client that matched a delegation refusal on
`type: unauthorized` should match `delegation_refused`; the status stays `401`.

## Measured

The rounding defect and all three delegation findings were measured on
2026-09-27 on a three-node cluster: the `gpt-4o-mini` call above through the
OpenAI door with a real key, and a vouchryx delegation revoked mid-run on the
Anthropic door, where every refused call read `reason=BadToken` in the log and
answered with the `x-fuse-key` sentence. The fixes are proven by tests, each red
first on 1.3.0, and planted mutants (rounding per part again, a fixed `htu`
again) each caught.
